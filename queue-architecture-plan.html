Babysitter: webhook-first PR queue

The queue is the source of truth. GitHub calls wake it; agents consume one coalesced PR generation. GraphQL is a targeted verification call, not the scheduler.

A burst of five webhooks for PR #1351 becomes one queue item for generation 42. The agent sees the merged JSON and does one pass.

2. One agent pass

ClaimOldest dirty PR.
Verify lease and generation.
→
Inspect snapshotUse stored checks, reviews, comments and head SHA. No discovery GraphQL.
→
One targeted refreshOnly if required data is missing or the head changed.
→
ActRepair CI/review/conflict, push one commit, or merge the verified SHA.
→
FinishPersist result. Wait for the next webhook. New generation during the pass remains queued.

Pullfrog rule

Pullfrog is an input event, not a permanent polling gate. If a matching review exists, use it. If no review arrives, issue one recovery request for the exact head. If Pullfrog is unavailable and there are no actionable findings, continue to the normal merge gate instead of spending repeated full agent passes.
